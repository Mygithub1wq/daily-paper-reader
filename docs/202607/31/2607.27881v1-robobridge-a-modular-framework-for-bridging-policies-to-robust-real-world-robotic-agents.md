## 摘要
视觉-语言-动作（VLA）模型作为机器人操作的一种可扩展方法引起了越来越多的关注。虽然这些模型是有效的动作预测器，但将它们部署为机器人代理时暴露了关键差距：没有故障恢复机制，长时程执行不一致，以及对观测、任务或实体变化的鲁棒性有限。现有解决方案通过模型重训练或特定于环境的模块分别解决这些局限性，但所需的是一个通用框架，能够系统地将预训练的VLA转化为机器人代理。我们提出了RoboBRIDGE，一个模块化框架，在五个协调模块（即Monitor、Perceptor、Planner、Controller和Robot Interface）之上提供编排层，从现成组件（包括预训练的VLA）组合出鲁棒的机器人代理。Monitor将快速故障检测与分层恢复配对，在错误级联之前纠正它们。当环境偏离当前计划时，Planner触发重新规划，而Perceptor异步更新场景理解，避免执行停滞。在Controller内部，原始技能微调将操作分解为具有专用LoRA适配器的领域不变原语，从而在使用VLA时减少对领域变化的敏感性。在跨越多个机器人平台和VLA主干的LIBERO、RoboCasa以及真实世界案例研究中，RoboBRIDGE始终优于独立策略和先前的增强VLA部署。这些结果表明，可靠的机器人代理能力不仅来自扩展动作预测器，还来自围绕它们的结构化编排。

## Abstract
Vision-Language-Action (VLA) models have attracted growing interest as a scalable approach to robotic manipulation. While these models are effective action predictors, deploying them as robotic agents exposes critical gaps: no mechanism for failure recovery, inconsistent execution over long horizons, and limited robustness to shifts in observations, tasks, or embodiments. Existing solutions address these limitations individually through model retraining or environment-specific modules, yet what is needed is a general framework that systematically transforms a pretrained VLA into a robotic agent. We present RoboBRIDGE, a modular framework that provides an orchestration layer over five coordinated modules, namely Monitor, Perceptor, Planner, Controller, and Robot Interface, to compose robust robotic agents from off-the-shelf components, including pretrained VLAs. The Monitor pairs rapid failure detection with hierarchical recovery to correct errors before they cascade. When the environment diverges from the current plan, the Planner triggers replanning while the Perceptor updates scene understanding asynchronously, avoiding execution stalls. Within the Controller, primitive skill fine-tuning factors manipulation into domain-invariant primitives with dedicated LoRA adapters, reducing sensitivity to domain shifts when a VLA is used. Across LIBERO, RoboCasa, and real-world case studies spanning multiple robot platforms and VLA backbones, RoboBRIDGE consistently outperforms both standalone policies and prior augmented VLA deployments. These results suggest that reliable robotic agency does not arise from scaling action predictors alone, but from structured orchestration around them.

### 1. 核心问题与整体含义（研究动机与背景）

- **问题背景**：视觉-语言-动作（VLA）模型已成为机器人操作领域的重要研究方向，能够将多模态观测和语言指令直接映射为低层动作。然而，一个强大的**动作预测器**并不等同于一个可靠的**机器人代理**。
- **核心缺口**：VLA模型以端到端前馈策略的形式部署时，存在三个关键缺陷：
  - **无故障恢复机制**：一次抓取失败或碰撞不会被察觉，错误会逐级级联放大。
  - **长时程执行不一致**：每一步推理相互独立，无法跟踪任务进度，也无法纠正累积误差。
  - **对领域偏移鲁棒性差**：当部署环境偏离训练分布（如观测变化、任务变化、本体变化）时，性能急剧下降。
- **现有方案的不足**：已有工作（如Code-as-Monitor、DoReMi、SAFE、SayCan等）分别针对单一失败模式进行修补，彼此割裂，均绑定特定模型架构或环境设置，缺乏统一解决方案。
- **核心论点**：论文类比LLM领域从"孤立文本生成器"到"通用代理"的演进过程（如LangChain、AutoGen等编排框架），指出VLA领域同样面临瓶颈——**缺的不是更好的策略模型，而是一个通用编排框架，将任意策略提升为完整的机器人代理**。可靠的机器人代理能力来源于围绕动作预测器的**结构化编排（structured orchestration）**，而非单纯扩大模型规模。

### 2. 方法论：RoboBRIDGE框架

RoboBRIDGE 由五个协调模块组成，将任意动作生成策略（不仅限于VLA）包装为鲁棒机器人代理，且无需重新训练基础模型：

#### 2.1 五个核心模块
- **Perceptor（感知器）**：将原始传感器观测转换为以物体为中心的场景状态，包含物体身份、3D位姿、语义属性（如可操作性、任务相关属性）。
- **Planner（规划器）**：接收精炼的场景状态和语言指令，将任务分解为有序的**原始技能（primitive skills）**序列（如MOVE、GRIP、ROTATE等），并附加上下文参数。
- **Controller（控制器）**：框架中的插槽位，由动作生成策略占据，将每个原始技能翻译为低层动作。可以是VLA、经典IK控制器或脚本程序。
- **Monitor（监控器）**：闭环验证执行结果，检测失败时触发分层恢复。
- **Robot Interface（机器人接口）**：抽象不同机器人的API、时序、安全限制和坐标变换，使上游逻辑可跨机器人/模拟器复用。

#### 2.2 关键机制一：两阶段监控与分层恢复（Two-phase Monitoring）
为解决"大多数步骤成功，全量诊断引入不必要延迟"的问题，监控分为两个阶段：
- **阶段一（轻量级成功检查）**：使用轻量模型 D_check 对当前观测 o_t 和预期计划上下文 c_t 输出二元成功标志 succ_t 和置信度 conf_t，使用受限输出格式抑制过长推理，约5Hz运行在控制循环之外，不阻塞执行。
- **阶段二（失败诊断与恢复）**：当检测到失败且置信度 ≥ γ_thresh 时，立即暂停机器人并调用诊断模型 D_diag 推断根因，并选择恢复策略。恢复策略为四级层次结构，按重新计算范围递增：
  1. **Retry（重试）**：重新执行当前原始技能；
  2. **Regenerate（重新生成）**：保留当前计划和感知状态下，重新生成轨迹；
  3. **Replan（重新规划）**：基于最新异步感知结果重新规划；
  4. **Re-perceive（重新感知）**：当物体状态不可靠时，强制完整重新感知后再规划。

#### 2.3 关键机制二：异步感知与分歧触发的反应式规划（Reactive Planning with Asynchronous Perception）
- **异步感知**：采用生产者-消费者架构，感知线程持续更新线程安全缓冲区 B（仅存最新结果），隐藏感知延迟，避免执行停滞。
- **分歧度量**：在每个原始技能完成后，对比当前计划所用感知状态 o_plan 与缓冲区最新感知状态 o_lat 的差异：

  Δ(ō_a, ō_b) = max_{i∈O_a∩O_b} [‖p_a^(i) − p_b^(i)‖₂] + λ·|O_a △ O_b|

  其中 p^(i) 为物体 i 的3D位置，O 为检测物体集合，△为对称差集，λ 加权物体出现/消失。

- **触发重规划**：当 Δ(ō_plan, ō_lat) ≥ τ 时，保留高层动作序列（如PICK→PLACE），仅基于最新感知结果重新生成当前及后续原始技能的空间参数，避免冗余的高层推理。

#### 2.4 关键机制三：原始技能微调（Primitive Skill Fine-tuning）
- **核心思想**：将操作分解为领域不变原始技能集合 P = {MOVE, GRIP, ROTATE, ...}，每个原始技能由专门的LoRA适配器处理，而非由单一骨干网络统一处理所有操作阶段。
- **实现方式**：在冻结的VLA主干 f_θ 上附加轻量LoRA模块 Δθ_k，每个适配器仅在该原始技能的演示数据上训练：

  f_{θ+Δθ_k} : (i, s_t, p_t) → a_t^(k)

- **控制器切换机制**：采用两层级解析器，存在对应原始技能的适配器时选择之，否则回退到所有注册适配器的平均值：

  RESOLVE(p_t) = Δθ_{p_t}（若适配器存在）; 否则 (1/|P|)·Σ_{p∈P} Δθ_p

- **动作生成与执行**：适配器预测7自由度增量动作 a_t = (δx, δφ, g)，其中 δx 为平移增量、δφ 为旋转增量、g 为夹爪指令。以笛卡尔速度命令发布，频率为 f_c；若有IK求解器，则将增量转换为绝对目标求解关节位置，IK失败时回退到速度控制。该双路径执行策略使同一控制器可适配不同运动学接口的机器人。

#### 2.5 完整算法伪代码（文字描述）
主流程为：初始化任务 → 重置环境 → 感知初始场景 → 生成初始计划 → 启动异步感知线程 → 对计划中每个原始技能循环执行：解析适配器 → 持续推理动作并执行 → 周期性轻量成功检查 → 失败且高置信时停止并诊断 → 执行分层恢复 → 技能完成后检查场景分歧度 → 若超阈值则更新场景状态并重新规划 → 全部完成后结束。

### 6. 主要结论与发现

1. **结构化编排是关键**：可靠机器人代理能力不是来自更大的动作预测器，而是来自系统的编排与协调机制。
2. **RoboBRIDGE一致优于独立部署**：在LIBERO上，平均成功率从35.5%提升至39.7%；在RoboCasa上，从3.7%提升至7.5%（排除PnP任务则从6.2%提升至11.4%）；全部3个VLA骨干上均有一致提升。
3. **监控与规划缺一不可**：有监控与无监控的差距显著，且该收益与LLM骨干的诊断能力正相关——Claude Opus 4.6增益最高（+8.1%），小模型（Gemini-3 Flash、Claude Haiku 4.5）几乎无提升。
4. **框架对控制器类型具有普适性**：LoRA微调+框架（27.1%）接近独立全参数微调（31.9%）；全参数微调+框架可达40.0%；经典IK控制器也能在框架内达到22.1%。
5. **模型内部自校正（CycleVLA）不足以替代外部编排**：CycleVLA独立部署平均仅7.5%，明显低于RoboBRIDGE的框架化部署。
6. **两阶段监控高效且有效**：轻量检查+按需诊断的分离避免了不必要的全量诊断延迟，并能防止错误级联。

### 7. 优点

- **策略无关的通用设计**：框架不依赖特定控制器架构，VLA、经典IK控制器均可插入，是"LLM代理编排"思想在机器人操作领域的系统移植。
- **模块化程度高**：Monitor、Perceptor、Planner、Controller、Robot Interface五个模块可自由组合替换，每个模块的功能边界清晰。
- **监控机制设计精巧**：两阶段分离（轻量检查+按需诊断）和四级分层恢复（retry→recover→replan→re-perceive）在计算开销与恢复深度之间取得良好平衡。
- **异步感知避免执行停滞**：生产者-消费者架构将感知延迟隐藏在控制循环之外，仅当场景实质分歧时才触发重规划，兼顾实时性与反应性。
- **原始技能+LoRA分解合理**：将操作分解为领域不变原语并配以专用低秩适配器，以极小参数量实现多阶段专业化，且适配器切换无需重载骨干。
- **框架收益与骨干能力互补**：论文发现监控收益依赖LLM的诊断推理能力，揭示了"外部框架+基座能力"的协同关系，而不是简单叠加。

### 8. 不足与局限

- **原始技能词汇有限**：当前覆盖单臂桌面操作行为，对接触丰富互动、可变形物体、双臂任务需要更丰富的原语和状态表示。
- **监控阈值与恢复规则手动设置**：未实现从交互数据中自动学习这些参数，限制了框架的泛化和自适应能力。
- **感知仍是瓶颈**：论文识别的两大主导失败模式：
  - 感知错误（Perception errors）：在杂乱场景中的遮挡或相似物体导致误识别/误定位，使下游原语基于错误物体姿态执行。
  - 不可恢复的操作失败（Unrecoverable manipulation failures）：接触丰富交互中错误已不可逆地改变环境状态，重试不再有意义。
  - 论文未能解决这两类问题，仅指出需要更强的验证与确认（V&V）机制。
- **RoboCasa上PnP类任务几乎无改进**：14个PnP任务中绝大多数成功率仍为0%，说明框架在处理需要精确空间操作的任务类型上存在系统性困难。
- **真实世界评估较弱**：仅有定性轨迹展示（图5），无真实场景的量化成功率统计，难以严格评估框架在实机上的表现水平。
- **实验样本量偏小**：每个条件约17次rollout，统计功效有限；未报告方差或置信区间。
- **算力资源未透明**：未披露训练基础设施配置，不利于复现和成本评估。
