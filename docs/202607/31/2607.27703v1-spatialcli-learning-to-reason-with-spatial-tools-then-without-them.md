## 摘要
视觉语言模型（VLM）越来越多地被用于具身智能体中，以解释视觉输入、推理空间关系，并基于该推理做出任务级决策。然而，一个根本性的能力不匹配仍然存在：通用VLM能够推理整体任务，但往往遗漏决定成败的视觉细节，而专用视觉模型能够捕捉这些细节，却无法将其转化为任务级决策。在这项工作中，我们提出了SpatialCLI，一个教VLM使用空间工具进行推理，并逐步内化它们所提供的专用感知能力的框架。SpatialCLI分三个阶段进行：（1）调用（Call）将专用视觉模型作为空间工具暴露出来，以增强VLM的感知；（2）学习（Learn）使用冷启动SFT和智能体强化学习来改进工具使用；（3）内化（Internalize）将成功的工具使用轨迹语言化，以内化专用感知能力。我们还引入了SpatialCLI-Bench，一个包含516个示例的基准测试，涵盖定位、分割、深度和姿态的组合感知。在MindCube上，SpatialCLI将Qwen3-VL-8B-Instruct从29.3%提升到使用工具时的84.6%，超过了使用工具的GPT-5.6 Sol（72.1%），而在内化后不使用工具时仍保持73.8%的性能。

## Abstract
Vision-language models (VLMs) are increasingly used in embodied agents to interpret visual inputs, reason about spatial relationships, and make task-level decisions based on that reasoning. However, a fundamental capability mismatch remains: general VLMs can reason about the overall task but often miss the visual details that determine success, while specialist vision models can capture those details but cannot translate them into task-level decisions. In this work, we propose SpatialCLI, a framework that teaches VLMs to reason with spatial tools and progressively internalize the specialist perceptual capabilities they provide. SpatialCLI proceeds in three stages: (1) Call exposes specialist vision models as spatial tools to augment the VLM's perception; (2) Learn uses Cold-Start SFT and agentic RL to improve tool use; and (3) Internalize verbalizes successful tool-use trajectories to internalize specialist perceptual capabilities. We further introduce SpatialCLI-Bench, a 516-example benchmark for compositional perception across localization, segmentation, depth, and pose. On MindCube, SpatialCLI raises Qwen3-VL-8B-Instruct from 29.3% to 84.6% with tools, surpassing GPT-5.6 Sol with tools (72.1%), while retaining 73.8% without tools after internalization.

### 1. 核心问题与研究动机

- **根本性能力不匹配**：通用视觉语言模型（VLM）擅长任务级语义理解、指令遵循和多步推理，但在精确定位、对象边界、度量深度和姿态估计等细粒度空间感知上不可靠；而 SAM 3、Depth Anything 3、VGGT 等专用视觉模型能提供可靠的局部感知证据，却无法理解任务需要哪些能力、组合多种感知输出或将其转化为任务级决策。
- **具身智能的现实需求**：真实世界任务往往需要按需组合多种空间感知能力（如"找到离我最远的泰迪熊"需要先分割识别所有候选对象、再比较深度、最后定位），单一能力的提升无法满足这一需求。
- **关键开放问题**：工具交互过程中积累的感知证据能否转换为监督信号，使 VLM 内化专用感知能力，从而在**不调用工具**的情况下也能直接推理？这关系到通往物理世界原生基础模型的路径。
- **现有工作的不足**：SpaceTools、AlloSpatial、S-Agent 等系统虽然组织外部工具进行智能体推理，但均未系统解决能力内化问题；现有基准大多孤立评估单一空间能力，无法考察模型协调多种互补能力的能力。

### 2. 方法论：SpatialCLI 三阶段框架

SpatialCLI 的核心思想是"先用工具，后学内化"——通过三个递进阶段将外部专用感知能力逐步转化为模型自身能力：

- **阶段一：Call（推断时工具增强）**
  - 将四个专用视觉工具注册到 ReAct 智能体循环中：
    - **Locate**：基于 Locate Anything + Grounding DINO 融合定位，返回边界框和中心点。
    - **Segment**：基于 SAM 3 实例分割，返回边界框、中心点和多边形边界。
    - **Depth**：基于 Depth Anything 3，查询指定图像点的度量深度（相机轴距离，米）。
    - **Pose**：基于 Orient Anything V2 + VGGT，返回对象朝向或跨视角相机运动。
  - VLM 每步先内部推理，再选择输出最终答案或调用工具；工具结果动态追加到交互历史中。
  - 暴露剩余工具调用预算，使 VLM 自主决定继续收集证据还是终止。

- **阶段二：Learn（智能体微调）**
  - **冷启动 SFT**：用 Qwen3.5-397B-A17B 作为教师模型生成工具交互轨迹，过滤无效格式、工具执行失败和答案错误的样本，建立基本工具交互行为（约 2,000 条高质量轨迹）。
  - **智能体 RL**：从 SFT 检查点出发，使用 GRPO（带 DAPO 非对称 Clip-Higher 边界和 token 级策略梯度约简）优化工具规划、参数生成、结果利用和终止决策；奖励基于最终答案与真实值的匹配或 BOPASK 点集分数。

- **阶段三：Internalize（轨迹引导的能力内化）**
  - **渐进式证据落地轨迹语言化**：
    - 逐步证据整合：每轮工具交互后，用提取器 Ψ_ext 将当前工具结果与显式视觉观察整合为证据-推理单元，保留跨轮依赖且不重复已整合内容。
    - 全局轨迹语言化：用全局语言化器 Φ_verb 将各轮证据整合为简洁的任务级推理链，不引入证据中不存在的实体或关系。
  - **双视角能力内化**：联合训练两个视角——
    - 能力内化视角：模型直接生成推理链和答案，不访问外部工具，从而内化专用感知能力。
    - 工具使用视角：保留原始工具交互结构，保持模型调用工具和利用结果的能力。
  - 联合损失：L_CI = L_internal + λ·L_agentic（λ=0.5），两部分均为监督 token 的平均负对数似然。

### 6. 主要结论与发现

- **SpatialCLI 工具提供有效的运行时空间增强**：工具增益随基础模型能力增强而减小（GPT-5.6 Sol 提升 6.1 点，Qwen3-VL-8B 提升 21.0 点），说明外部专用感知对空间能力较弱的模型价值最大。
- **训练同时提升直接回答和实际工具使用**：所有 SpatialCLI 变体在全部评测子集上均优于对应的初始模型；内化与工具使用可以共存，不存在此消彼长的关系。
- **冷启动 SFT 对 RL 至关重要**：RL w/ Tools + SFT 工具调用数保持约 2.56 次稳定，而 w/o SFT 从 3.36 膨胀到 6.74 次，训练稳定性显著更优。
- **能力内化随数据呈缩放趋势**：w/o Tools 分数从 40.1% 升至 74.0%，CII 从 45.6 升至 61.6，两者同步上升，说明是真正的能力迁移而非答案记忆。
- **内化随模型容量持续扩展，而工具使用趋于饱和**：w/ Tools 分数在三种规模间差异仅 ≤1.0 点，而 w/o Tools 和 CII 随容量显著提升——外部工具压缩了模型间差异，内化则依赖模型参数容量。
- **结构化工具返回优于可视化返回**：显式坐标和多边形是提升的主要来源，且更易于转换为文本内化监督。
- **渐进式证据整合和双视角训练都不可或缺**：完整双视角方案达到最佳 w/o Tools 72.7% 和 w/ Tools 91.3%，且输出更紧凑。

### 7. 优点与亮点

- **"先用工具再内化"的路径设计**：将外部工具使用和内部能力内化统一在同一框架中，避免了直接微调无法获取细粒度监督的困境。
- **渐进式轨迹语言化**：先逐轮整合证据、再全局语言化的两阶段设计，保留了跨轮依赖，避免长上下文中证据间的依赖关系被掩盖，也防止答案条件化的证据重构。
- **双视角联合训练**：同时优化能力内化视角和工具使用视角，实现了"鱼与熊掌兼得"，为后续工作提供了可借鉴的范式。
- **基准构建严谨**：SpatialCLI-Bench 采用多阶段构建（模型预标注 → 专家视觉模型证据 → 条件生成 → 独立人工审核），每一事实条款要求有证据支持，人工审核保留率 71.67%，质量有保障。
- **CII 指标设计细致**：针对每种能力设计专门的相似度函数（IoU 匹配、AbsRel 指数转换、圆形角度距离、轴向量余弦相似度），能定量衡量内化程度而非仅看任务分数。
- **实验覆盖全面**：从训练动态、数据扩展、模型容量到消融和敏感性分析，多层次验证了方法有效性。

### 8. 不足与局限

- **工具覆盖范围和可靠性受限**：当前仅支持结构化感知输出（框、多边形、深度、姿态），不支持多模态输出（如分割掩码图像直接作为监督）；单个工具失败会级联影响推理。
- **任务范围窄**：仅覆盖感知中心型任务（定位、分割、深度、姿态的组合推理），未涉及 VLA 工具集成、动作生成和物理交互。
- **部分消融仅在单一模型（8B）上验证**：工具返回格式消融、λ 敏感性分析等都只在 Qwen3-VL-8B-Instruct 上完成，泛化性待验证。
- **评估种子未固定**：虽然报告三次运行均值，但评估种子随机可能引入方差；工具调用的随机性也可能影响可复现性。
- **教师依赖**：SFT 和轨迹语言化都依赖 Qwen3.5-397B-A17B 作为教师模型，教师模型的质量和偏差会传递到最终模型。
- **训练数据规模有限**：37,000 个训练任务的共享池相对有限，更大规模数据的扩展趋势尚未验证。
- **存疑点**：论文提到 Qwen3-VL-8B-Instruct 加 SpatialCLI Tools 后 MindCube 从 29.3% 提升至 84.6%，如此大的提升幅度可能部分来源于工具本身的强感知能力而非 VLM 的决策能力，其泛化性和稳健性有待在更多样化的真实场景中验证。
