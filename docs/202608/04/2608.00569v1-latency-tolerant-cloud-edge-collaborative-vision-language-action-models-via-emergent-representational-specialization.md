## 摘要
在移动机器人上部署十亿参数的视觉-语言-动作（VLA）策略引发了一个系统冲突：语义推理受益于云端GPU，而闭环控制必须在网络延迟和抖动下本地响应。现有分层和异步策略提高了吞吐量，但其慢路径表征仍可能过时到达，或者需要显式调度和延迟提示。我们提出CloudEdgeVLA，一种将时间错位视为表征学习问题的云边协作策略。云端VLA将延迟观测编码为慢变化的任务特征，而轻量级边缘头将最新可用的云特征与当前本地视觉结合。训练时，当前帧和随机延迟帧在新鲜路径和过时路径中与相同的当前动作目标配对。这一目标鼓励云表征保留任务级信息，同时边缘路径提供状态敏感修正。在四个LIBERO套件中，CloudEdgeVLA在40步均匀延迟窗口下保持了63.8%–78.0%的成功率，而VLASH最高仅6.4%，所评估的单路径基线最高3.0%。通过从控制回路中移除阻塞同步，该设计为可扩展VLA部署提供了一条实用路径，其中云模型可以增长，而边缘计算保持轻量化和响应性。

## Abstract
Deploying billion-parameter Vision-Language-Action (VLA) policies on mobile robots creates a systems conflict: semantic reasoning benefits from cloud GPUs, whereas closed-loop control must respond locally despite network delay and jitter. Existing hierarchical and asynchronous policies improve throughput, but their slow-path representations can still arrive stale or require explicit scheduling and delay cues. We introduce CloudEdgeVLA, a cloud-edge policy that treats temporal misalignment as a representation-learning problem. A cloud VLA encodes delayed observations into slowly varying task features, while a lightweight edge head combines the latest available cloud feature with current local vision. During training, current and randomly delayed frames are paired with the same current action target in fresh and stale paths. This objective encourages the cloud representation to preserve task-level information while the edge path supplies state-sensitive corrections. Across four LIBERO suites, CloudEdgeVLA retains 63.8--78.0% success with a 40-step uniform-delay window, whereas VLASH reaches at most 6.4% and the evaluated single-path baselines at most 3.0%. By removing blocking synchronization from the control loop, the design offers a practical route to scalable VLA deployment in which cloud models can grow while edge computation remains lightweight and responsive.

- **系统级矛盾**：亿级参数的 VLA（视觉-语言-动作）模型需要云端 GPU 进行语义推理，但移动机器人的闭环控制要求本地实时响应。云端推理受网络延迟、抖动和数据丢失影响，返回的特征描述的是**拍摄时刻的场景**，而非**执行时刻的场景**。
- **现有方案的不足**：
  - **阻塞等待**新特征会降低控制频率；**非阻塞执行**最新特征则引入时间错位。
  - 分层/异步策略（如 MResT、DP-VLA、HiRT、SmolVLA）虽提升吞吐，但慢路径表征仍可能过时到达，或需要显式调度/延迟提示。
  - 动作分块重规划假设环境在执行期间静止，会累积陈旧误差。
- **核心问题**：跨网络传输的表征在**年龄可变且未知**时如何保持有用？论文将时间错位视为**表征学习问题**而非调度问题。
- **主要思路**：类比 Kahneman 的 System 1/System 2 —— 云端 VLA 提供**慢变的"做什么"**任务上下文，边缘头利用当前本地视觉处理**"现在怎么做"**的状态敏感控制。边缘永不阻塞，始终消费最新收到的云特征。

## 2. 方法论：核心思想、技术细节与流程

### 核心思想：涌现表征特化（Emergent Representational Specialization）

- 云端特征在延迟训练信号压力下，自发编码**对时间位移不敏感的任务级信息**（目标、策略、物体语义），而非瞬时状态。
- 当前边缘视觉特征负责编码**状态敏感信息**，二者互补。

### 系统架构（三组件）

| 组件 | 位置 | 角色 | 细节 |
|------|------|------|------|
| 云端 VLA 骨干 f_θ（System 2） | 云端 | 生成慢变规划特征 | 7B OpenVLA + LoRA 适配，处理观测 o 与指令 ℓ，输出 h = f_θ(o, ℓ) ∈ R^{L×D}（L=T×A 为动作块位置数） |
| 边缘视觉编码器 v_ψ（System 1 感知） | 本地 | 提取实时视觉特征 | 冻结的 SigLIP-Base，z_t = v_ψ(o_t) ∈ R^{D_v}，始终由当前观测计算，零延迟 |
| 边缘动作头 g_ϕ（System 1 控制） | 本地 | 融合新旧特征输出动作 | 对规划特征按动作维度做 mean-pool，投影视觉特征到同一隐空间，拼接后经残差 MLP 输出动作块 â_t = g_ϕ(h_{t−k}, z_t) ∈ R^{T×A} |

### 配对帧双路径训练（Paired-Frame Dual-Path Training）

1. **配对帧提取**：从同一 episode 取 W 个连续观测窗口 W_t = {o_{t−W+1}, …, o_t}，构造当前帧 o_t 和延迟帧 o_{t−d}（d ~ Uniform(1, W−1)）。
2. **双前向**：两帧分别过云端骨干，得到 h_fresh 和 h_stale（均接收梯度，不截断）。
3. **双预测**：两套规划特征都与**同一实时视觉特征** z_t 融合，得到 â_fresh 和 â_stale。
4. **双路径损失**：

   L = (1−λ) ||â_fresh − a_t||₁ + λ ||â_stale − a_t||₁

   - L_fresh 保证同步操作能力；L_stale 训练动作头用实时视觉补偿过期特征。
   - λ 采用**课程学习**：训练前期从 0 逐步升至 λ_max，先学强表征再学延迟不变性。

### 部署协议（非阻塞）

- 边缘采集 o_t → 异步发送云端 → 云端返回 h（可能来自旧帧 o_{t−k}）→ 边缘计算 z_t → 融合生成 â_t → 执行。
- **目标函数对延迟帧的梯度**：∇_θ L_stale = ∇_θ ||g_ϕ(f_θ(o_{t−d}, ℓ), v_ψ(o_t)) − a_t||₁。随机 d 使仅依赖瞬时状态的云特征不可靠，迫使云特征保留跨时间稳定的任务信息——这是一种**软性的、非强制**的时间位移不变性。

## 6. 主要结论与发现

1. **延迟容忍的核心结果**：d_max=40 时，CloudEdgeVLA 在四个套件保持 63.8%–78.0% 成功率；VLASH 最高仅 6.4%，单路径基线最高 3.0%。宏平均延迟 AUC 达 90.8%（VLASH 仅 32.4%），同步成功率保留率为 76.5%（VLASH 1.8%）。
2. **套件鲁棒性差异**：Long 套件下降最大（−27.9pp），Goal 最稳定（−18.5pp），但最坏情况仍比最强基线高 63.3pp。
3. **消融关键发现**：
   - 加入冻结 SigLIP-Base 编码器带来 +63.5pp（31.6%→95.1%），证明**实时视觉接地**是主要贡献；更大的 SigLIP-SO400M 仅 +0.7pp，支持轻量级 Base 模型用于边缘部署。
   - 仅 stale 监督已达 89.2%（远超 fresh-only 的 54.8%），联合监督再 +5.9pp，表明**延迟曝光是鲁棒性的主因**，fresh 路径提供互补接地。
4. **机制定位**：d=20 时骨干漂移降低 59.2%（0.391→0.160），陈旧转移增益 κ 降低 72.7%（1.082→0.295），使动作漂移降低 88.9%（0.423→0.047）。鲁棒性来自**云骨干稳定性 + 动作头对残余漂移的衰减**两个方面。
5. **真实机器人**：静态任务 1000ms RTT 下 CE-VLA 保持 80%（VLASH 0%），动态任务 400ms 下 90%（VLASH 30%）。
6. **延迟容忍是习得的接口属性**，而非仅靠推理调度。

## 7. 优点

- **问题视角新颖**：把网络延迟从调度问题转化为表征学习问题，提出"非阻塞接口"概念——边缘始终消费最新特征，无需时钟/频率对齐。
- **简洁高效的设计**：配对帧双路径训练仅需在现有 VLA 训练流程上增加一条 stale 路径，无需显式不变性损失或延迟元数据。
- **课程学习策略**：λ 渐进增加，先学强表征再学延迟不变性，训练更稳定。
- **机制透明度高**：通过 D_h/κ/D_a/E_demo 等指标分解鲁棒性来源，避免将端到端成功简单地归因于"表征特化"；反事实审计主动揭示边缘视觉直接校正的局限性，体现了**学术诚实性**。
- **部署友好**：边缘组件轻量（冻结 SigLIP-Base + 小 MLP），云端骨干可独立扩展（LoRA 适配），兼容现有 VLA 架构。
- **全面的实验覆盖**：从闭环仿真到真实机器人，从聚合成功率到逐 cell 动作块分析，多层次验证。

## 8. 不足与局限

- **延迟假设局限**：仅测试均匀延迟窗口（上限 40 步）；训练窗口 W=21，d_max>20 已超出训练分布但仍有较好表现，不过**无限延迟或断连场景完全未覆盖**——长时间断连可能连任务级上下文都失效。
- **计算成本**：配对帧训练需**双骨干前向传播**（fresh + stale），训练开销约为单路径的两倍。
- **感知模态有限**：冻结的 RGB 编码器无法利用深度、力/触觉等模态，可能限制精细操作的鲁棒性。
- **真实机器人验证薄弱**：仅 10 trials/condition、单一平台（Franka + 工作站级边缘设备），非嵌入式硬件，统计功效不足以支撑强结论；不是硬件效率基准。
- **机制声称的证据缺口**：反事实审计发现当前 120k 检查点的边缘视觉**直接校正作用极弱**（仅 0.03% 的 rescue fraction），鲁棒性主要由骨干稳定性和头衰减贡献——这意味着论文标题中的"edge grounds cloud"机制在该检查点下尚未被强证据支持，实际机制与声称机制存在偏差。
- **离线诊断局限**：每任务仅 1 个 episode 的 8 个采样式时间步，共 10 个任务级样本，置信区间较宽；延迟以环境步计，非硬件无关的毫秒延迟。
- **未涉及工程化问题**：论文未讨论时间戳特征、本地回退策略、多机器人并发云请求、安全约束等实际部署必要组件。
